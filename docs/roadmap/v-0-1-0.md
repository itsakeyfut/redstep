# v0.1.0 — Attack-to-prevention vertical slice (MVP)

- **Version**: `v0.1.0`
- **Status**: released
- **Theme**: Attack-to-prevention vertical slice (MVP)
- **Released**: 2026-10-16

> **In one sentence**: run a genuine attack (a native SQL injection) against a deliberately vulnerable target inside an isolated, egress-less lab, capture what succeeded as replayable evidence, and prove that a fix closes it.

## Goal

v0.1.0 is the one vertical slice that proves the whole loop end to end before any of it is broadened: an attacker capability runs from inside an isolated lab, succeeds against a vulnerable target, is recorded as evidence a verdict is drawn from, and the recorded success replays as closed against a fixed build. Everything that comes after widens one axis of this slice (more techniques, real tools, network boundaries, multi-step paths); this release exists so there is a working spine to widen. It deliberately runs a single native technique single-hop, so the spine is real without waiting on the tool adapters and topology that later releases add.

## Scope

- Isolated Docker lab: per-segment `internal` networks with no egress, a boundary self-check that runs before any attack and refuses to proceed when isolation is broken, and RAII teardown that cleans up even on an interrupted run — realizes `ADR-0003` / `ADR-0006` / `ADR-0011`.
- Scope gate: a capability receives its target only from the scope resolver, and an out-of-scope or unscoped target is a hard error before any action — realizes `ADR-0006` / `ADR-0021`.
- Intensity ladder: a capability defaults to `Safe`; `Controlled` and `Aggressive` require an explicit, unforgeable opt-in — realizes `ADR-0002`.
- Native capabilities behind one intensity-gated trait: a TCP reachability capability and an HTTP vantage point, run from the attacker's position inside the lab — realizes `ADR-0002`.
- A native SQL-injection check with the full exploit -> capture -> fix -> replay loop against the playground, including the redirect and request-authority guards that keep the probe inside its scope — realizes `ADR-0009` / `ADR-0022` (one technique, extended in v0.2.0).
- Pass/Fail/Inconclusive oracle: the observation (what happened) is kept separate from the verdict (whether it is acceptable), and a weak or conflicting signal lands in Inconclusive rather than a confident PASS — realizes `ADR-0010`.
- Append-only evidence, one canonical JSON that every report projects from, and an executable rustc-style failure diagnostic emitted by the oracle — realizes `ADR-0004` / `ADR-0005` / `ADR-0009` (the JSON and terminal renderers; SARIF and HTML come in v0.6.0).
- A Success Witness that captures enough to replay a success deterministically against the same environment, with a pinned replay — realizes `ADR-0022`.
- A deliberately-vulnerable playground target (database, API, web) built only as Docker images and excluded from the workspace, with a `fixed` build that patches the vulnerability for the replay side of the loop.
- Continuous integration (fmt, clippy, doc and the suite on Linux and Windows, plus a Linux leg that builds the playground images so the lab tests run), and a crates.io release via release-plz and Trusted Publishing with a crate README.

## Attack coverage

- [SQL Injection](../attacks/sql-injection.md) — `http_sqli_vantage`.

## Out of scope

- Real external-tool adapters (nmap, sqlmap): the original roadmap line named them, but they were reconciled out in #33 and deferred; v0.1.0 ships a native SQLi check and native TCP reachability instead — deferred to `v0.4.0` (external offensive tooling), `ADR-0007`.
- Port/reachability boundary, firewall gateway, DMZ, and the external -> internal multi-hop — deferred to `v0.3.0` (network boundaries), `ADR-0011`.
- Multi-step attack scenario and the pivot (external -> web -> api -> db) — deferred to `v0.5.0` (multi-step scenarios), `ADR-0012`.
- App-security beyond the one SQLi (path traversal, IDOR, SSRF, OS command injection, SSTI) — delivered in `v0.2.0`.
- SARIF, HTML, the attack-graph visualization, and the scenario DSL — deferred to a later release (reporting and visualization, then the scenario DSL), `ADR-0001` / `ADR-0004` / `ADR-0005`.

## Depends on

None. This is the initial release.

## Release criteria

- [x] The SQL-injection exploit -> capture -> fix -> replay loop runs against the playground and the fix closes it (the Docker-gated `sqli_fix_and_replay_closes_the_loop`), with a positive control that the fixed target still works.
- [x] The boundary self-check refuses to run when isolation is broken, and the boundary demo shows the internet attacker cannot reach the database (#19, #26).
- [x] A non-`Safe` capability cannot run without an unforgeable intensity opt-in (#9; the seal is compiler-held).
- [x] An out-of-scope or unscoped target is a hard error before any action.
- [x] Every report projects from one canonical JSON, and the oracle emits a rustc-style failure diagnostic; a weak or conflicting signal is Inconclusive, not a confident PASS.
- [x] A Success Witness replays the recorded success deterministically against the same environment.
- [x] CI runs fmt, clippy, doc and the suite on Linux and Windows, plus the playground lab leg, and the crate publishes to crates.io with a README.
