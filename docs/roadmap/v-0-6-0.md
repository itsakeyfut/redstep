# v0.6.0 — Reporting and visualization

- **Version**: `v0.6.0`
- **Status**: planned
- **Theme**: Reporting and visualization
- **Released**: —

> **In one sentence**: turn the canonical evidence into the outputs people actually consume and share — an HTML report with the attack graph drawn, SARIF for code-scanning ingestion, and an ATT&CK/OWASP coverage view — with a shared report safe to pass around.

## Goal

Up to v0.5.0 a run's result lives in the terminal and the canonical JSON. For redstep to be useful to a team rather than only the developer who ran it, the result has to be shareable in the vocabularies tools and people already use: SARIF so a CI gate or a code-scanning dashboard can ingest it, HTML so a person can read the report and see the attack graph drawn, and a coverage view that answers "which ATT&CK/OWASP techniques did we exercise, and how did each land". This release is pure projection: every output renders from the one canonical JSON, so a new report cannot disagree with the evidence. It also makes a shared report safe to hand to someone else, by redacting the credentials a reproduction may have captured.

## Scope

- SARIF output projected from the canonical JSON, representing an attack path as codeFlows, valid against the SARIF 2.1.0 schema so a gate or dashboard can ingest it — realizes `ADR-0005`.
- An HTML report rendered from the canonical JSON, including the attack graph drawn from the graph data v0.5.0 projects — realizes `ADR-0004` / `ADR-0005`.
- An ATT&CK/OWASP coverage view: the techniques a run exercised and their verdicts, derived from the catalog tags and the run's evidence, so coverage is readable alongside the findings — realizes `ADR-0016`.
- Credential redaction on export: secrets a reproduction captured are redacted when a report leaves the machine, so a report is safe to attach to an issue or a pull request — realizes `ADR-0005`, `ADR-0021`.
- Every new output is a projection from the single canonical JSON: a renderer adds a view, never a second source of truth — realizes `ADR-0005`.

## Attack coverage

None. This release renders existing evidence; it adds no attack technique.

## Out of scope

- The scenario DSL — deferred to `v0.7.0`, `ADR-0001`.
- Importing other tools' findings (ZAP, Burp, Nessus, BloodHound): this release is output and sharing, not ingestion of external results — deferred to a later release (platform expansion and interop).
- Cloud, Kubernetes, Windows/Active-Directory, and AI/adversary-emulation outputs — deferred to the later platform and adversary-emulation releases.

## Depends on

v0.1.0 (the one canonical JSON every report projects from, and the terminal renderer alongside which these sit), v0.2.0 (the ATT&CK/OWASP tags in the catalog the coverage view reads), and v0.5.0 (the attack-graph data this release draws).

## Release criteria

- [ ] SARIF output validates against the SARIF 2.1.0 schema and represents an attack path as codeFlows; a code-scanning ingest accepts it.
- [ ] An HTML report renders from the canonical JSON and draws the attack graph, showing the same verdicts as the terminal and the JSON (a projection, not a second source).
- [ ] An ATT&CK/OWASP coverage view lists the exercised techniques and their verdicts, derived from the catalog tags and the run.
- [ ] A shared or exported report redacts credentials a reproduction captured, proven by a test that a known seeded secret does not appear in any export.
- [ ] Every new output is a projection from the one canonical JSON; no renderer reads a value the JSON does not carry.
- [ ] The workspace version is bumped to 0.6.0 and the release is cut.

## Risks and open questions

- Projection drift: a renderer that computes a field differently from the canonical JSON is a report that lies about the run. Each renderer is pinned to the JSON's shape, and the canonical JSON being the single source (ADR-0005) is the guard; a round-trip test alone is not enough (a renamed field round-trips), so the shape is pinned with a literal.
- Redaction completeness: a secret missed in any one output is a leak. Redaction is applied at the canonical-JSON boundary so every projection inherits it, and a test asserts a seeded secret is absent across every output, not only one.
- SARIF conformance is an external standard that moves; the schema version is pinned and checked in CI.
