# v0.5.0 — Multi-step attacks and pivoting

- **Version**: `v0.5.0`
- **Status**: planned
- **Theme**: Multi-step attacks and pivoting
- **Released**: —

> **In one sentence**: chain exploits into an attack path — external -> web -> api -> db — where each hop's success becomes the foothold and credentials for the next, with the attacker's growing state and the resulting attack graph recorded as evidence.

## Goal

Until now each check is one hop: a single exploit against a single target. Real compromise is a chain — break the web tier, use what that yields to reach the internal API, use that to reach the database. v0.5.0 is the machinery that makes a chain a first-class thing: an attacker state that grows as footholds and credentials are gained, so one capability's success is the starting position of the next, and the whole path is projected as an attack graph from the recorded steps. It is the first release where the answer is not "this one thing is exploitable" but "here is how far a real intrusion gets, step by step, and what each step needed." It depends on v0.3.0 (where a step can reach) and v0.4.0 (how a step exploits), and it stops short of a full command-and-control implant, which is a later adversary-emulation release.

## Scope

- The attacker state as a growing asset set: a foothold, a credential, or a reachable position gained by one capability is available to the next, and the evidence records which asset unlocked each step — realizes `ADR-0012` / `ADR-0004`.
- The multi-step attack path run end to end: external -> web -> api -> db, each hop gated by the previous hop's success, so breaking one hop stops the chain (a negative control, not just a happy path) — realizes `ADR-0012`.
- A remote-shell pivot: a capability runs from a gained foothold's position inside the lab, not only from the original external or assume-breach vantage — realizes `ADR-0012` (a lightweight session, not a C2 implant).
- Lateral movement with captured credentials: a credential gained at one hop is reused to reach a host or service not reachable from the start, and the move is attributed in the evidence.
- The attack graph projected from the evidence facts: the multi-step path is a graph derived from the recorded steps, not a hand-built structure, so the record and the graph cannot disagree — realizes `ADR-0004`.

## Out of scope

- A full command-and-control implant lifecycle (Sliver, Mythic): v0.5.0's pivot is a lightweight session, the implant and its lifecycle are the adversary-emulation release — deferred to a later release, `ADR-0020`.
- Windows/Active-Directory lateral movement (pass-the-hash, Kerberos ticket attacks, OS credential dumping) — deferred to the platform-expansion release that has a real domain.
- Cloud lateral movement (assumed-role chaining, metadata-to-IAM) — deferred to the cloud platform release.
- Rendering the attack graph (SARIF, HTML, the visual graph): v0.5.0 produces the graph as data projected from evidence; drawing it is a later release (reporting and visualization).
- The scenario DSL that would let a user author a chain declaratively — deferred to a later release (the scenario DSL), `ADR-0001`.

## Depends on

v0.3.0 (where a step can reach: the assume-breach vantage, the reachability and boundary model the chain moves across), v0.4.0 (how a step exploits: the tool adapters and exploitation capabilities each hop uses), v0.2.0 (the native exploits a hop can use), and v0.1.0 (the lab, the evidence and witness path each step records into).

## Release criteria

- [ ] The attacker state grows: a foothold or credential gained by one capability is available to the next, and the evidence names the asset that unlocked each step (ADR-0012, ADR-0004).
- [ ] The external -> web -> api -> db chain runs end to end, each hop gated by the previous hop's success, with a negative control that breaking one hop stops the chain rather than silently reporting the rest as reached.
- [ ] A remote-shell pivot runs a capability from a gained foothold's position, not only from the starting vantage, confined to the egress-less lab and intensity-gated.
- [ ] Lateral movement with Valid Accounts: a captured credential reaches a service not reachable from the start, and the evidence attributes the move to that credential.
- [ ] The attack graph is projected from the recorded evidence facts, not hand-built, so a step missing from the evidence is missing from the graph.
- [ ] A weak or ambiguous step lands Inconclusive and does not falsely advance the chain or the graph.
- [ ] The workspace version is bumped to 0.5.0 and the release is cut.

## Risks and open questions

- Chaining is where a false PASS or a mis-attribution compounds: a step credited to the wrong foothold, or a chain reported as advancing without a real foothold, launders one lie through several hops and is read as a whole intrusion path. Evidence attribution (ADR-0004) and the per-hop negative control are what hold it; the attack graph being projected from evidence, not asserted, is part of the same guard.
- The remote-shell pivot is an isolation-sensitive capability (a shell running inside the lab): it stays egress-less and intensity-gated, and the boundary self-check runs before it, like every other capability.
- Scope pressure in two directions: toward a real C2 (kept to a lightweight session; the implant lifecycle is a later adversary-emulation release) and toward Windows/AD or cloud lateral movement (kept to the platform releases that have a real domain or a real cloud).
- Open: whether Privilege Escalation and Session Hijacking ride in this release or in a later Web/API round — to settle at /spec.
