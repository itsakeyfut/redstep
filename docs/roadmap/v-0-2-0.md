# v0.2.0 — Native Web/API security checks

- **Version**: `v0.2.0`
- **Status**: released
- **Theme**: Native Web/API security checks
- **Released**: 2026-10-30

> **In one sentence**: cover the major Web/API injection and access-control techniques beyond the first SQL injection — path traversal, IDOR, SSRF, OS command injection (in-band and blind out-of-band), SSTI — each as a genuine exploit -> capture -> fix -> replay loop against your own app, recorded with ATT&CK/OWASP tags.

## Goal

v0.1.0 proved the attack-to-prevention loop on one native technique. This release widens that one axis: it takes the HTTP vantage and the SQL-injection seam from v0.1.0 and turns them into a shared app-security check seam, then builds the rest of the common Web/API techniques on it, so a developer can point redstep at their own app and get the same exploit-and-prove-the-fix loop for each. It also adds the out-of-band channel (an in-lab canary) the loop needs for techniques whose success is a server-side side effect rather than a response the probe can read, which is what makes SSRF and blind command injection expressible at all.

## Scope

- A shared HTTP witness seam extracted from the SQL-injection check, so every body-marker technique runs through one path (the probe, the marker-in-body witness, the scope and redirect guards) — realizes `ADR-0004` / `ADR-0010`.
- Native path-traversal, IDOR / broken-access-control, SSRF, OS command injection, and SSTI checks on that seam, each with the full exploit -> capture -> fix -> replay loop against the playground and a positive control that the fixed target still works — realizes `ADR-0009` / `ADR-0022`.
- An out-of-band witness mechanism: an in-lab canary records a coerced callback (a per-probe token in its logs), attributed to the app, not the canary. It carries SSRF and the blind, out-of-band variant of command injection, whose success never appears in the probe's own response — realizes `ADR-0023`.
- ATT&CK and OWASP tags, first-class on every technique: a catalog under `docs/attacks/` names each technique, its tags, and the capability that exercises it (or `none` when unbuilt), so coverage is visible — realizes `ADR-0016`.
- Offline guards that keep the above honest without a Docker daemon: the diagnostic gate and the draft capability are pinned offline for every native check, and a drifted cross-boundary constant (a witness, an injection template, a required image tool) fails a pure test rather than only a self-skipping Docker one — realizes `ADR-0009`.
- The Docker-gated lab tests default-skip locally and are opted in by CI, so a routine local run creates zero lab containers while the exploit paths still run where a lab exists.

## Out of scope

- Consolidating the body-marker and out-of-band witness classifiers into one fail-closed path is the last piece of this release, not a separate one; it is part of the release's work, not a deferral.
- Corroborating in the capability that an out-of-band coercion actually fired (so a confident "not exploitable" is never vacuous): the out-of-band negative is only as strong as the target's ability to make the callback, which is documented but not yet enforced — deferred to `v0.3.0`, `ADR-0010` / `ADR-0023`.
- Redacting credentials carried in a reproduction when a report is shared — deferred to a later release, with the SARIF/HTML renderers it constrains.
- The scenario DSL, and the SARIF / HTML / attack-graph visualization — deferred to a later release (reporting and visualization, then the scenario DSL), `ADR-0001` / `ADR-0004` / `ADR-0005`.
- Real external-tool adapters (nmap, sqlmap, ffuf), network boundaries, and multi-step attack paths — deferred to `v0.4.0` (tooling), `v0.3.0` (network boundaries), and `v0.5.0` (multi-step), `ADR-0007` / `ADR-0011` / `ADR-0012`.

## Depends on

v0.1.0: the isolated lab and boundary self-check, the scope gate, the intensity ladder, the Pass/Fail/Inconclusive oracle, the append-only evidence and canonical JSON, the Success Witness and pinned replay, and the HTTP vantage and native SQL-injection seam this release generalizes.

## Release criteria

- [x] Native checks for path traversal, IDOR, SSRF, OS command injection (in-band and blind out-of-band), and SSTI each run the exploit -> capture -> fix -> replay loop against the playground, and each pairs the fix with a positive control that the fixed target still performs its benign function.
- [x] The out-of-band canary mechanism records a coerced callback, attributes the finding to the app rather than the canary, and replays a recorded witness as closed against the fixed build.
- [x] Every technique has a `docs/attacks/` entry tagged with ATT&CK and OWASP and naming its capability, so coverage is readable from the catalog.
- [x] The diagnostic gate and the draft capability are guarded offline for every native check, and a drifted cross-boundary constant fails a pure test, not only a self-skipping Docker one.
- [x] The Docker-gated lab tests default-skip locally and run opted-in on CI.
- [x] The body-marker and out-of-band witness classifiers are consolidated into one fail-closed classifier, with every fail-closed property preserved under its named tests.
- [x] The workspace version is bumped to 0.2.0 and the release is cut (crates.io and the tag).

## Risks and open questions

- The out-of-band "not exploitable" is confident only that this coercion did not call back, not that the target is safe: for a blind check the callback depends on tooling on the target (a reachable outbound client), so a genuinely injectable target without one reads the same as a safe one. This is documented in the catalog and the capability doc, and closing it in the capability is tracked for `v0.3.0`; it does not block this release.
- The classifier consolidation touches the shipped, fail-closed witness and replay path; the risk is a verdict-soundness regression during consolidation, held by the existing classifier and parse-round-trip tests that each fail on a mutation.
