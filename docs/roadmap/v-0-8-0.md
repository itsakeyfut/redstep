# v0.8.0 — Platform expansion: cloud, Kubernetes, IaC (mock and real)

- **Version**: `v0.8.0`
- **Status**: planned
- **Theme**: Platform expansion (cloud, Kubernetes, IaC) with mock and real backends
- **Released**: —

> **In one sentence**: extend the lab beyond Docker app tiers to cloud, Kubernetes, and infrastructure-as-code targets, through an Environment Provider that backs a target with a mock (such as LocalStack) or a real provider, and run the cloud-native and container-platform attacks against them.

## Goal

Up to v0.7.0 a target is a container in the Docker lab. Real systems are more: a cloud account, a Kubernetes cluster, infrastructure defined as code. This release adds the Environment Provider that lets a target be backed either by a mock (LocalStack and the like, which keeps everything inside the egress-less lab) or by a real provider (the developer's own cloud or cluster, under explicit authorization), and runs the cloud-native and container-platform attacks against them. The mock backend is the default and the safe path; the real backend is where the project's hardest safety question lives, because a real cloud target is real infrastructure, and reaching it is exactly what the isolation model otherwise forbids. So the real backend is gated, not assumed.

## Scope

- The Environment Provider: a target's environment is backed by a mock provider or a real one, and the same scenario runs against either; the mock backend is in-lab and egress-less, the real backend is an explicit, authorized opt-in — realizes `ADR-0013`.
- Cloud targets and the cloud-native attacks: instance-metadata abuse, public storage exposure, IAM privilege escalation, and cloud service/infrastructure discovery, each testable against the mock backend and, under authorization, a real account — realizes `ADR-0013`.
- Kubernetes and container-platform targets: container escape to host, runtime-socket exposure, credentials in container images, and container/resource discovery — realizes `ADR-0013`.
- Infrastructure-as-code targets: security tests over IaC definitions (misconfiguration in Terraform or Kubernetes manifests) brought into the same evidence and verdict model — realizes `ADR-0013`.
- The scope, isolation, and risk-tier model extended to the cloud boundary: a real-backend target is still resolved only through the scope gate, and reaching a real provider is governed by the distribution/authorization risk tier — realizes `ADR-0006` / `ADR-0011` / `ADR-0021`.

## Out of scope

- Windows and Active Directory targets, and the host-OS and AD identity techniques — deferred to `v0.9.0` (they need a real domain, a different backend).
- Importing other tools' findings (ZAP, Burp, Nessus, BloodHound) — deferred to `v0.9.0`.
- AI-driven testing and adversary emulation (C2) — deferred to a later release, `ADR-0015` / `ADR-0020`.

## Depends on

v0.1.0 (the scope gate, the isolation model, and the evidence path the Provider plugs into), v0.3.0 (the reachability and boundary model that now has to hold at a cloud boundary), and v0.4.0 (the tool-adapter mechanism cloud-attack tools such as Pacu or CloudFox would plug into).

## Release criteria

- [ ] The Environment Provider backs a target with a mock provider (in-lab, egress-less) and the same scenario runs against it unchanged; the mock path creates no real-infrastructure reach.
- [ ] The cloud-native attacks (metadata abuse, storage exposure, IAM privesc, cloud discovery) run against the mock backend with the exploit -> capture -> fix -> replay loop and positive controls.
- [ ] The container-platform attacks (escape, socket exposure, image credentials) run against a Kubernetes/container target.
- [ ] IaC security tests run over an IaC definition and produce evidence and a verdict in the same model.
- [ ] A real-backend target is reachable only after an explicit, authorized opt-in gated by the risk tier (ADR-0021), is still resolved through the scope gate, and a test proves the mock backend is the default and no real reach happens without the opt-in.
- [ ] The workspace version is bumped to 0.8.0 and the release is cut.

## Risks and open questions

- This release holds the project's hardest safety question: a real cloud or cluster backend is real infrastructure, and reaching it is the off-scale failure the isolation model exists to prevent. The mock backend (in-lab, egress-less) is the default and needs no new guarantee; the real backend must be an explicit, risk-tier-authorized, scope-gated opt-in, and it likely earns its own ADR when implemented, because it changes what "the lab is egress-less" means. Nothing about a real provider is reached by default.
- Mock fidelity: a mock (LocalStack) does not behave exactly like a real provider, so a check that passes against the mock is not proof against the real one. The evidence must record which backend a result came from, so a mock result is never read as a real-provider guarantee.
- Sizing: cloud plus Kubernetes plus IaC plus the Provider is large; the natural split, if needed, is IaC and the container-platform set into a v0.8.x follow-up.
- Open: whether cloud-attack tools (Pacu, CloudFox) ride here as adapters or in a later tooling round — settle at /spec.
