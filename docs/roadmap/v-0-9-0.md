# v0.9.0 — Windows, Active Directory, and tool interop

- **Version**: `v0.9.0`
- **Status**: planned
- **Theme**: Windows and Active Directory targets, and importing other tools' findings
- **Released**: —

> **In one sentence**: bring real Windows and Active Directory targets into the lab, run the host-OS and identity techniques against them — credential dumping, Kerberos ticket attacks, alternate authentication material, MFA bypass — and import findings from other tools (ZAP, Burp, Nessus, BloodHound) into the same evidence and attack graph.

## Goal

The identity and host-OS techniques that matter most in real intrusions — stealing credentials, forging Kerberos tickets, reusing authentication material, bypassing MFA — need a real Windows and Active Directory environment to be exercised honestly; the catalog has kept them unbuilt precisely because the software-defined Docker lab has no domain. This release gives them one: a Windows/AD target backed through the Environment Provider from v0.8.0. It also makes redstep a place other tools' results come together: a finding from ZAP, Burp, Nessus, or BloodHound is imported into the same canonical evidence and the same attack graph, so a mixed toolchain produces one picture rather than several. Imported findings are treated as observations to be corroborated, not as verdicts to be trusted.

## Scope

- Windows and Active Directory targets in the lab, backed through the Environment Provider (a real VM / domain), so the identity techniques have a real domain to run against — realizes `ADR-0013`.
- The host-OS and AD identity techniques: OS credential dumping, Kerberos ticket attacks, use of alternate authentication material, and MFA bypass, each with the exploit -> capture -> fix -> replay loop where a fix is expressible — realizes the identity genre of the catalog.
- Tool interop, importing: a finding from an external tool (ZAP, Burp, Nessus, BloodHound) is ingested into the canonical evidence and projected into the attack graph, carrying its source so a reader knows which tool observed it — realizes the interop goal.
- Imported findings as corroboration, not verdict: an external tool's finding is an observation that raises or lowers confidence alongside redstep's own, never a confident verdict on its own — realizes `ADR-0010`.

## Out of scope

- AI-driven testing and adversary emulation (the AI operator, C2) — deferred to a later release, `ADR-0015` / `ADR-0020`.
- Cloud and Kubernetes targets — delivered in `v0.8.0`.
- Exporting to other tools (this release imports their findings; the export side is the reporting release `v0.6.0`).

## Depends on

v0.8.0 (the Environment Provider that now backs a Windows/AD VM), v0.5.0 (the lateral-movement and credential model the AD techniques extend), and v0.6.0 (the canonical evidence and attack graph that imported findings are projected into).

## Release criteria

- [ ] A Windows/Active-Directory target can be brought up through the Environment Provider and is scope-gated and isolated like any other target.
- [ ] The identity techniques (credential dumping, Kerberos, alternate authentication material, MFA bypass) run against the AD target and record evidence; their catalog `capability` fields are set.
- [ ] A finding from at least one external tool (ZAP, Burp, Nessus, or BloodHound) is imported into the canonical evidence and projected into the attack graph, carrying its source.
- [ ] An imported finding is treated as an observation corroborated into a verdict, never read as a confident verdict on its own (RK-002 shape).
- [ ] The workspace version is bumped to 0.9.0 and the release is cut.

## Risks and open questions

- A real Windows/AD VM is heavy and licensed: the image supply and licensing are real maintenance, and the VM, while self-hosted in the lab, still has to be held inside the isolation boundary like any other target (closer to containable than v0.8.0's real cloud, but the egress and scope guarantees must still hold at the VM boundary).
- Import fidelity: another tool's finding is its claim, in its format and its confidence model, not redstep's. Ingesting it as a corroborating observation (not a verdict) is the guard; a parser that reads a tool's raw severity as redstep's verdict would launder an external claim into a confident answer.
- Fix-and-replay for some identity techniques may be only partially expressible (a domain misconfiguration's "fix" is a domain change), so some checks land a verdict without a replayable fix; that is acknowledged, not hidden.
