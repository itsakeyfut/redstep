# v0.4.0 — Real offensive tooling

- **Version**: `v0.4.0`
- **Status**: planned
- **Theme**: Real offensive tooling
- **Released**: —

> **In one sentence**: run the mature tools a real attacker uses — nmap, sqlmap, Metasploit, Hydra, plus the Nuclei and Trivy scanners — inside the egress-less lab as intensity-gated capabilities whose raw signals are corroborated into verdicts, pointed at imported real-vulnerable apps as well as the playground.

## Goal

Up to v0.3.0 every check is native Rust. That is deliberate (a native check is deterministic and needs no external binary), but a developer's trust in "redstep says my app is exploitable" grows when the same finding is reproduced by the mature tool a real attacker would reach for. This release builds the tool-adapter mechanism that wraps an external tool as a capability behind the same intensity gate and evidence shape, then lands the tools themselves: recon, injection, exploitation, credential attacks, and the vulnerability scanners. It also stops the lab being only the bespoke playground: a known-vulnerable application can be imported as a target, so the tools are exercised against the kind of software they are used against in the wild. The tools corroborate the native checks rather than replace them, which is the point: two independent methods agreeing is a stronger verdict than either alone.

## Scope

- The tool-adapter plugin mechanism: a real external tool is wrapped as an intensity-gated capability emitting canonical evidence, through the three role contracts, starting from static (compiled-in) plugins — realizes `ADR-0002` / `ADR-0007`.
- Offensive tool adapters run inside the egress-less lab: nmap (recon and port/service scan), sqlmap (SQL injection), Metasploit (exploitation of a reachable service), Hydra (credential brute-force) — realizes `ADR-0002` / `ADR-0007`.
- Scanner tier: Nuclei (template-based web/service vulnerability scan) and Trivy (container-image and dependency vulnerability scan), each mapping findings to catalog techniques and capabilities — realizes `ADR-0007` (the scanner role).
- Existing vulnerable-app import: a known-vulnerable application can be brought up as a target alongside the bespoke playground, so the tools are exercised against real-world-shaped software — realizes `ADR-0008`.
- Attacker image and attack data as pinned, auditable supply: the lean/full tool profiles the attacker image composes from, and the version-pinned data packs the tools need, with SBOM and license review — realizes `ADR-0018` / `ADR-0019`.
- Corroboration of a tool's raw output into an observation and verdict: a noisy or ambiguous tool signal is never read as a confident verdict on its own, and a tool-backed finding corroborates the matching native check — realizes `ADR-0010` (RK-002 shape).

## Out of scope

- Multi-step exploit chaining and the pivot: using a tool's foothold on one service to reach and exploit the next is v0.5.0, which depends on these adapters — deferred to `v0.5.0`, `ADR-0012`.
- Cloud, Kubernetes, and Windows/Active-Directory tooling (Pacu, CloudFox, BloodHound) — deferred to the platform-expansion releases.
- Command-and-control and adversary emulation (Sliver, Mythic) — deferred to a later release (adversary emulation and C2), `ADR-0020`.
- ike-scan (IKE/IPsec VPN recon): named in the original roadmap but it needs a real VPN endpoint the software-defined lab does not provide — kept a candidate, `capability: none`, until a lab VPN target exists.
- SARIF, HTML, the attack-graph visualization, and the scenario DSL — deferred to a later release (reporting and visualization, then the scenario DSL).

## Depends on

v0.1.0 (the egress-less lab, the intensity ladder a tool must be gated by, the scope gate, the canonical evidence shape), v0.2.0 (the native checks the tools corroborate), and v0.3.0 (the vantage a recon or exploitation tool runs from, and the hardened capability foundation and `redstep-attacks` crate the adapters plug into).

## Release criteria

- [ ] The tool-adapter mechanism wraps a real external tool as an intensity-gated capability that emits canonical evidence, through the three role contracts, and a tool cannot bypass the intensity gate.
- [ ] nmap, sqlmap, Metasploit, and Hydra each run inside the egress-less lab and produce an observation that is corroborated into a verdict; a tool's raw signal alone never reads as a confident verdict (RK-002).
- [ ] Nuclei and Trivy run and their findings map to catalog techniques, setting the corresponding capabilities.
- [ ] A known-vulnerable application can be imported and used as a target, not only the bespoke playground (ADR-0008).
- [ ] The attacker image composes from pinned lean/full tool profiles and the data packs are version-pinned, with an SBOM and a license review (ADR-0018, ADR-0019).
- [ ] At least one tool-backed check corroborates its native counterpart (e.g. sqlmap agrees with the native SQL-injection check) in the same run.
- [ ] Every real tool is confined to the egress-less lab; a boundary self-check proves it cannot reach outside before any tool runs.
- [ ] The workspace version is bumped to 0.4.0 and the release is cut.

## Risks and open questions

- Real offensive tools are the highest isolation risk in the project: a mature tool that can reach real infrastructure is the off-scale failure. The pinned attacker image and the egress-less lab (`ADR-0006`, `ADR-0019`) and the pre-run boundary self-check must hold the line; nothing about a real tool is trusted to behave.
- Tool-output fidelity: every tool emits noisy, versioned, sometimes ambiguous output. Parsing it into an observation is the recurring edge-case and false-signal risk (RK-002); an unparseable or ambiguous result is Inconclusive, never a confident verdict.
- Supply-chain weight: pinned data packs and tool profiles with SBOM and license review are real maintenance; the cross-cutting governance and data-pack upkeep run continuously, not only in this release.
- Sizing: this is a large release (the adapter mechanism, four offensive tools, two scanners, app import, and the image/data-pack supply). It is intended to be a substantial bump; if it needs to split, the natural seam is the scanner tier and app import into a v0.4.x follow-up.
