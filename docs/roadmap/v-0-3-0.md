# v0.3.0 — Network boundaries and post-breach reach

- **Version**: `v0.3.0`
- **Status**: planned
- **Theme**: Network boundaries and post-breach reach
- **Released**: —

> **In one sentence**: from an assume-breach foothold inside the lab, measure what an attacker can reach and where a boundary stops them — enforcing a real port/firewall boundary, not just network membership — and record the blast radius as evidence.

## Goal

v0.2.0 answers "is this app exploitable". The next question a developer has once an app is breached is "how far does it get them" — which segments and services a foothold can reach, and which boundaries actually hold. v0.3.0 makes that measurable: it realizes the assume-breach vantage as a first-class attacker position inside the lab, enforces an inter-segment boundary as a real gateway rather than only network membership, and reports the reachable set from that vantage. It deliberately measures reach, not exploit chaining: it answers "where can an attacker get to", leaving "how an attacker chains one exploit into the next" to v0.5.0, which depends on this and on v0.2.0's exploits. This release also hardens the capability foundation the vantage checks stand on, because that foundation is now carrying a second vantage and a growing set of techniques.

## Scope

- The assume-breach vantage realized on an internal segment and guarded: a capability can run from an attacker position the environment declares inside a segment, and cannot be forged onto a segment the environment did not declare — realizes `ADR-0017` / `ADR-0012`.
- An inter-segment boundary enforced as a gateway, not only by network membership: a service meant to be reachable "only through the intended path" is verified reachable that way and unreachable otherwise, so the boundary is a real firewall/port rule rather than a mere `internal` flag — realizes `ADR-0011` (membership plus a firewall on the boundaries that need one).
- A blast-radius containment test: from the assume-breach vantage, which services and segments are reachable and which boundaries held, checked per element (not a representative sample) and recorded as evidence attributed to the vantage — realizes `ADR-0011` / `ADR-0012`.
- Out-of-band coercion corroboration: a confident "not exploitable" over the canary channel requires the coercion to have been shown able to fire, so a blind negative is no longer vacuous — realizes `ADR-0010` / `ADR-0023` (#100).
- Capability-foundation hardening now that a second vantage and a growing technique set ride on it: the intensity gate held by the compiler on the vantage path (#44), a constructor for `EvidenceDraft` so field additions do not break external construction (#43), an offline guard for the capability each vantage method stamps (#94), and the attack techniques aggregated into a `redstep-attacks` crate, one module per technique (#89) — realizes `ADR-0002` / `ADR-0004`.

## Out of scope

- Multi-step exploit chaining, the external -> web -> api -> db pivot, remote-shell pivot and lateral movement (a foothold that grows by chaining exploits) — deferred to `v0.5.0`, `ADR-0012`. v0.3.0 measures reach; it does not chain exploits.
- Exploitation of Remote Services as an exploit technique (as opposed to mere reachability) — deferred to `v0.5.0`.
- Real external-tool adapters (nmap, sqlmap, scanners) — deferred to `v0.4.0`, `ADR-0007`.
- Layer-2 and network-media techniques (adversary-in-the-middle, sniffing, DNS spoofing, VLAN hopping) — out of the software-defined lab's scope (need a radio, a switch, or real L2), kept `capability: none` in the catalog.
- Cloud, Kubernetes, and Windows/Active-Directory discovery — deferred to the platform-expansion releases.
- SARIF, HTML, the attack-graph visualization, and the scenario DSL — deferred to a later release (reporting and visualization, then the scenario DSL).

## Depends on

v0.1.0 (the isolated lab, the boundary self-check, the native TCP reachability capability this extends across segments, the scope gate and intensity ladder) and v0.2.0 (the out-of-band canary channel #100 corroborates, the evidence and witness path, and the technique set #89 aggregates).

## Release criteria

- [ ] An assume-breach vantage can be declared on an internal segment, a capability runs from it, and it cannot be forged onto a segment the environment did not declare (a named test fails on the forgery).
- [ ] An inter-segment boundary is enforced beyond membership: a service reachable only through the intended path is verified reachable that way and unreachable otherwise, with a positive control and per-element coverage (every member, not a sample).
- [ ] The blast-radius test reports, from the assume-breach vantage, the reachable set and which boundaries held, as evidence attributed to the vantage, and a weak or probe-side failure lands in Inconclusive, not a confident "contained".
- [ ] Network Service Discovery runs from the vantage and records the reachable services; its catalog `capability` is set.
- [ ] A confident out-of-band "not exploitable" requires the coercion to have been shown able to fire (#100), closing the vacuous-negative gap documented in v0.2.0.
- [ ] Capability foundation hardened: the intensity gate is compiler-held on the vantage path (#44), `EvidenceDraft` has a constructor (#43), the capability each vantage stamps is guarded offline (#94), and the techniques live in a `redstep-attacks` crate (#89).
- [ ] The workspace version is bumped to 0.3.0 and the release is cut.

## Risks and open questions

- The inter-segment gateway is the largest new piece and the highest-consequence: a boundary that reads enforced but is not is a false "contained" (a scope/isolation failure, off CLAUDE.md's scale). It must be held by the boundary self-check with a positive control and per-element coverage (`ADR-0011`, the RK-008/RK-009 shape), not by a representative probe.
- Scope pressure toward the pivot: the temptation is to chain one reachable service's exploit into the next. That is v0.5.0; v0.3.0 stops at reachability so it stays sized for one developer.
- Open: whether to extend the discovery to container resources (Container and Resource Discovery) in this release or defer it — to settle at /spec.
